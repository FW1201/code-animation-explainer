# 分鏡工藝：每一幕先是一張會動的封面

`storyboard.json` 管「每一幕講什麼、多長」；這份文件管「每一幀長什麼樣、鏡頭之間怎麼接」。跳過這一步的結果是時間表思維（第幾秒出現什麼元素），不是畫面思維（這一幀長什麼樣）。動效全對、畫面卻像示意圖，就是這樣來的。

**順序固定：先擺定格幀，再編排動作。**

## 1. 封面測試：每一幕的定格幀規則

隨機暫停影片的任一幀，這一幀都應該能直接當封面用。好封面＝**1 個具體主角＋≤3 個活躍元素＋1 條清楚的視線引導**。

| # | 規則 | 自檢 |
|---|---|---|
| 1 | **≤3 個活躍元素是每一幀的上限**，不是每幕的總數。新元素進場，舊元素就要退場（淡出、退到背景、變暗變模糊都算） | 隨便挑 3 個時間點暫停，數同畫面活躍元素 |
| 2 | **推近（zoom）的終點必須是具體的東西**：關鍵數字、那個字、那行程式碼、實驗器材上的刻度。背景紋理不配推近。倍率 <1.25x 不值得推（例外：開場 1.06x 定場微推） | 推近的終點能用一個名詞說出來嗎？ |
| 3 | **視線引導線＝鏡頭動線**：一幕只有一條引導線（箭頭、人物視線、閱讀方向），鏡頭沿著它走 | 給人看 3 秒，他的視線路徑和你的鏡頭計畫一致嗎？ |
| 4 | **字與畫分工**：大字每次 2–8 字（中文），講重點；畫面負責呈現過程。字落在構圖預留的空白處，不壓主角 | 遮掉畫面只看字，重點還在嗎？遮掉字只看畫面，構圖還成立嗎？ |
| 5 | **用百分比描述構圖**：「實驗裝置居中偏左 55%、刻度特寫框在右上 30%、標題距上緣 8%」。百分比可直接翻成 CSS | 構圖描述裡有至少 3 個百分比嗎？ |
| 6 | **前中後景三層**：寫出前景／中景／背景各是什麼、誰遮住誰；這就是視差（parallax）素材。層速比 0.35／0.7／1.4，相鄰層差 ≥2 倍才看得出 | 說得出三層各是什麼嗎？ |
| 7 | **先留缺口再補上（setup → payoff）**：幕的開頭留一個未完成的東西（空格、問號、半座橋），這一幕的動作負責補完 | 開頭幀和結尾幀並排，看得出「什麼被補完了」嗎？ |
| 8 | **抽象概念要具體化，而且選有過程的動作**：「蒸發」＝水分子一顆顆離開水面；「介詞『對』」＝箭頭從主語射向對象；「篩選」＝一堆卡片被篩子留下三張 | 這個意象能用一個動詞概括嗎？ |
| 9 | **風格全片定一次，構圖每幕換**：配色、字型、材質從 `direction-approved.md` 來，不換；構圖（置中特寫／三欄／對角）每幕不同 | 任兩幕比較：風格看不出差別，構圖一眼不同 |
| 10 | **3 公尺測試（教室版）**：教室投影，最後一排離螢幕約 10 公尺。關鍵帧縮到手機螢幕大小，最大的字還要看得清楚。不要因為「反正會動」就把字縮小 | 縮成手機大小還讀得出來嗎？ |

## 2. 景別：用 zoom 倍率說話

| 景別 | 倍率 | 看什麼 | 教學用途 |
|---|---|---|---|
| 遠景 | 0.8x | 全局＋留白 | 開場、統整、案例關係地圖 |
| 全景 | 1x（開場 1.06x 微推） | 完整畫面 | 多數幕的基準 |
| 中景 | 1.3–1.45x | 一個區塊 | 講解某一步驟、某一欄 |
| 近景 | 1.8x | 單一元件、單筆資料 | 強調關鍵字、單一數值 |
| 特寫 | 2.3x（上限） | 規則 2 的具體錨點 | 答案揭曉、易錯處 |

- 相鄰兩幕不要同景別（看起來像畫面跳一下），也不要遠景直接跳特寫（會暈）。
- 結尾一律回到全景／遠景，並停留 ≥0.8 秒；不要停在推近的狀態就結束。
- 運鏡的數量預算與實作見 `motion-language.md` §3。

## 3. 教學能量骨架：先劃掉停留時間，再排動效

一支多幕的教學影片，節奏不要平均分配。依下面四段排：

| 段 | 片長占比 | 能量 | 教學任務 | 硬指標 |
|---|---|---|---|---|
| ① 引起動機 | 8–12% | 低→中 | 一個問題、一個反差、一個生活現象 | 問題字卡停留 ≥1.5 秒，給學生想 |
| ② 建立概念 | 12–18% | 低，**全片最慢** | 核心概念第一次完整呈現（hero element 登場） | 主角完整動作弧 ≥3 秒；這段工藝做到最好 |
| ③ 例證爬升 | 55–60% | 中高與低交替 | 每幕一個例子或步驟，由簡到繁 | 每 1–2 個例證後插一張**呼吸字卡** |
| ④ 統整收束 | 13–16% | 全片峰值→停 | 所有例子回到同一張圖上（全家福）＋一句結論 | 結論停留 ≥2 秒；最後回全景 |

**呼吸字卡**：2–8 個字的大字＋大片留白＋零裝飾（例：「所以，差在哪裡？」）。它讓學生消化、讓節奏降下來。不要把它做成另一個資訊畫面。

**排片順序**：
1. 列出例證／步驟，數出幕數。
2. 先從總長裡劃掉不能動的停留時間：問題字卡 ≥1.5s、關鍵結果前懸停 0.5s、每批動效結束後靜止 0.5s、結論 ≥2s、結尾全景 ≥0.8s。
3. 剩下的時間才分給動效；高能量幕不能連續兩幕。
4. 每個接縫選轉場（§5），轉場時間從相鄰兩幕扣，不另外加。

短片（≤20 秒，例如課堂開場短動畫）可改用單段節奏：觸發 15%／生成 15%／過程 40%／揭曉 20%／停住 10%。

## 4. 分鏡卡：寫程式之前的交付物

每幕一行，八欄都要填。寫進 `storyboard.json` 每幕的對應欄位（見 `assets/storyboard.template.json`），也可以另存 `shotlist.md` 給使用者看。

```
| # | 時間 | 景別 | 運鏡＋動機 | 構圖（百分比） | 關鍵動效（一幕一個） | 轉場到下一幕 | 驗收時間點 |
```

- **時間**：起訖秒數，轉場已含在內。
- **景別**：§2 五檔之一＋倍率。
- **運鏡＋動機**：「靜止」也可以，但要寫為什麼；每次推近都要寫錨點（規則 2）。
- **構圖**：百分比＋前中後景。
- **關鍵動效**：這一幕只講一個動效（例：「箭頭從主語射向對象」）。其他元素只做進出場。
- **轉場**：從 §5 選，不能空白，不能寫「直接切」。
- **驗收時間點**：每幕預先寫 1–2 個秒數，做完就截那幾幀檢查。先定標準，免得做完後覺得「看起來還行」。

範例（3 分鐘「近義介詞：跟／對／給」）：

| # | 時間 | 景別 | 運鏡＋動機 | 構圖 | 關鍵動效 | 轉場 | 驗收 |
|---|---|---|---|---|---|---|---|
| 0 | 0–14s | 全景 1.06x→1x | 定場微推，讓畫面一開始就是活的 | 三個介詞大字橫排居中 50%，下方問句 20% | 三字同時亮起又同時暗下，留一個問號 | 共享元素：「對」放大成下一幕主角 | 6s、13s |
| 1 | 14–40s | 中景 1.35x | 推近「對」，錨點＝箭頭起點 | 主語卡左 25%、對象卡右 70%、箭頭橫跨中線 | 箭頭由主語射向對象（有方向） | 一鏡平移到「給」 | 28s、39s |

## 5. 轉場：依前後兩幕的關係選

| 前後兩幕的關係 | 首選 | 備選 |
|---|---|---|
| 時間跳躍（「幾年後」「實驗完成後」） | 黑場字卡 | 白場淡出淡入 |
| 同一張圖的不同區域 | **一鏡平移，不切** | — |
| 對比（前／後、A／B、正例／反例） | 遮罩擦去（mask wipe） | 左右分割畫面 |
| 遞進、因果（答案在下一幕） | **共享元素**：上一幕的元素飛成下一幕的主角 | 形變（morph） |
| 能量落差大（呼吸字卡→高能量幕） | 白閃 | 快速橫搖（whip pan） |
| 能量落差小（例證之間） | 交叉淡化 ≥8 幀 | 焦點接力（前景模糊→下一幕清楚） |
| 換章節（Vox 風） | 斜切色塊掃過（`engines.md`） | — |
| 換場景（皮影風） | 燈暗→換景→燈亮（`puppet-style.md`） | — |

三條紀律：一個接縫只用一種轉場，不疊加；轉場時間從相鄰兩幕扣；全片沒有未經設計的硬切。

**配音片的切點**：鏡頭變化與轉場對齊到旁白的停頓（句與句之間），只能提前、不能延後，最多提前 0.8 秒。觀眾在聽覺空檔移動視線最輕鬆。停頓位置可從 `captions/cues.json` 的字幕間隙找到。

## 6. 教學資訊出場順序：每種教學任務有自己的文法

同樣是「出現三個元素」，順序錯了學生就看不懂。先判斷這一幕在做哪一種教學任務，再照它的順序排出場與停留：

| 教學任務 | 出場順序 | 停留重點 | 常見錯誤 |
|---|---|---|---|
| **定義** | 詞（大字）→ 一句話定義 → 一個例子 → 一個非例子 | 詞與定義同畫面停 ≥ 定義字數÷4.5＋1.5 秒，再出例子 | 例子比定義先出現；只有例子沒有非例子 |
| **步驟** | 目標（最後要得到什麼）→ 第 1 步 → … → 結果，前一步縮小但留在畫面 | 每步完成後停 0.5 秒（`M.hold`）再下一步 | 前一步消失，學生回頭找不到 |
| **比較** | 兩者同時出現（左右並排、同大小）→ 逐項對照 → 標出差異 → 一句總結 | 差異標出後停 ≥1.5 秒 | 先講完 A 再講 B，學生記不住 A |
| **因果** | 因 → 箭頭 → 果；多因時先全部列出，再一條一條連 | 箭頭畫出的速度＝旁白說「所以」的速度 | 果先出現，再倒回講因 |
| **分類** | 上層類別 → 分類標準（一句話）→ 子類由上而下逐層長出 → 每類一個代表 | 每層長完停 0.5 秒 | 先撒散點再連線；分類標準沒說 |
| **問題→解答** | 問題（停留讓學生想）→ 錯誤直覺（可選）→ 線索 → 解答 | 問題卡停 ≥2 秒，解答前懸停 0.5 秒 | 問題一出現就給答案 |

分鏡卡的 `role` 寫教學能量骨架的段位（引起動機／建立概念／例證爬升／統整收束），`task` 寫上表的教學任務；兩個都寫，畫面順序才有依據。

## 7. 閱讀時間：讓學生讀得完

| 項目 | 規則 |
|---|---|
| 字幕 | 停留 ≥1.8 秒；每秒 ≤6 字（國小 ≤4.5）；說完之後若下一句還沒來，多留 0.6 秒 |
| 畫面字卡 | 文字動畫結束後停 ≥ 字數÷4.5＋1.5 秒 |
| 標題卡 | ≥4 秒 |
| 標籤（圖上的短名詞） | 不檢查，但要在旁白說到它之前或同時出現 |
| 要快 | 用更少的字，不是更早切走 |

畫面上要學生讀的文字寫進 `storyboard.json` 每幕的 `on_screen`（`[{"text", "in", "out", "kind": "card|title|label"}]`，秒數為幕內時間），建置字幕後檢查：

```bash
python scripts/read_check.py captions/cues.json --storyboard storyboard.json --timeline captions/timeline.json
```

不足就拆短句、刪字、或在這句後面加停頓（腳本加 `[pause]`）。

## 7.5 視覺化邏輯：畫面要「證明」旁白，不是裝飾旁白

每一幕先問：這句旁白的**論證結構**是什麼？再選對應的圖形結構，不要只是把關鍵字畫成插圖。

| 旁白在說 | 圖形結構 | 範例（`examples/handdrawn-skill-demo`） |
|---|---|---|
| 一個原因造成很多不同結果 | **發散**：一個輸入 → 亂射的箭頭 → 一排結果，中間放「≠」 | s1：提示詞「手繪風」→ AI → 五幕各畫各的 |
| 一個規則讓很多東西一致 | **樹狀分支**：一個來源 → 一條總線 → 整齊的短箭頭，中間放「＝」 | s2：風格卡 → 五幕照同一張畫 |
| 改變前後 | **同版面對照**：上一幕的版面原封不動搬過來，只換掉會變的部分 | s1 與 s2 用同一排縮圖，觀眾一眼看出差別 |
| 照順序發生 | **編號**：畫到哪一步就亮出號碼，畫完淡掉 | s5：Excalidraw 圖依圖層順序 1→8 |
| 原料 → 成品 | **左右對照＋中間一個動詞箭頭**（「匯入」「套用」） | s5：原色原圖 → 匯入 → 風格色版本 |
| 同一內容的多種樣子 | **同一張圖快切，再收成宮格** | s3：同一頁教材 × 8 種風格卡 |

結構相同的幕（問題／解法）要用**同一個版面**，差異才看得出來；結構不同的幕要換版面，畫面才不會重複。

## 8. 開工檢查（分鏡完成的定義）

- [ ] 每幕八欄填齊，寫進 `storyboard.json`
- [ ] 每幕定格幀過了規則 1（≤3 元素）、3（引導線）、5（百分比）
- [ ] 景別沒有同檔連切、沒有遠景直跳特寫
- [ ] 停留時間先劃掉了，呼吸字卡插了
- [ ] 每個接縫都選了轉場
- [ ] 每幕都預寫了驗收時間點
- [ ] 每幕寫了 `task`（教學任務），出場順序照 §6；要讀的字寫進 `on_screen`
- [ ] 情緒高點或概念轉折放了一個風格卡的原生招式（`native_move`）；運鏡只從風格卡的 `camera_vocab` 選
- [ ] 這一幕要用的照片、圖示、插畫已列出，照風格卡 `assets` 處理（`visual-resources.md` §2）
- [ ] 資訊密度：一幕＝標題＋一個主圖＋最多一張便利貼；和旁白重複的字卡刪掉
- [ ] 每幕寫得出它的圖形結構（發散／樹狀／對照／編號／前後），而且和旁白的論證一致（§7.5）
- [ ] 術語白話化：把旁白全文讀一遍，列出觀眾可能不懂的詞（參數名、程式術語、英文縮寫）。能刪就刪，不能刪的第一次出現要附一句白話或比喻，並把對照表寫進 `script.md`。只有內部才懂的詞（seed、roughness、hex 色碼…）不進旁白
- [ ] 推廣／工具介紹片要有「下一步」幕：怎麼安裝（實際指令或按鈕，逐字打出來讓人看得到）、裝好後第一句話怎麼說；片尾放網址
- [ ] 灰盒驗證：先用灰色方塊＋文字標籤排出 3 個驗收時間點的畫面截圖，確認構圖成立，再做正式畫面
