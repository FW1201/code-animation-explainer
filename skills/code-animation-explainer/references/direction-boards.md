# 方向板：先給三張看得見的畫面，再讓使用者選風格

## 為什麼要有這一步

使用者沒看過畫面，就沒辦法真的選風格。問「你要 Vox 風還是手繪風？」得到的答案常常是隨口一說，做完一幕樣片才發現不對，整片返工。而且模型自己挑，幾乎每次都挑最安全的那種極簡。

所以腳本確認後、錄音前，先做**三張方向板**擺在一起讓使用者挑。三張的成本約 15–20 分鐘，比做完一整片再改便宜很多。

## 什麼時候要做

| 情形 | 方向板 |
|---|---|
| 新影片／新互動教材 | **要做**，使用者指定了風格也要做（在該風格內做三種詮釋） |
| 使用者說「直接產出」「不用給我選」 | 跳過，由你選一張，**但要寫 `direction-approved.md` 記下原話與你選了什麼、為什麼** |
| 同一支片子的修改（換一幕、改字、重錄） | 不做，方向已經選過 |
| 純機械操作（轉檔、改字幕錯字、重新渲染） | 不做 |

使用者指定風格（例如「皮影戲風」）時，三張的差別放在詮釋上：暖黃幕布版／暗場剪影版／彩色鏤空版。風格詞縮小選擇範圍，但仍由使用者決定。

## 方向板長什麼樣子

每張方向板是一張 1920×1080 的**風格板**，用 `scripts/style_apply.py` 直接產生（左邊是套好風格的範例畫面，右邊是色票＋對比度、字型、動態參數、招牌動作）：
1. **範例畫面**：用真實腳本內容（挑最能代表全片的那一幕，通常是「建立概念」）寫成 `sample.json` 傳進去。不要用 Lorem ipsum 或「標題文字」。
2. **色票與語意**、**字型與字級**、**easing 與時長**：由風格卡自動列出，使用者看得到「選這張就是選這組參數」。
3. **一句定位＋參照作品＋色彩理由**：風格卡的 `positioning`、`benchmarks`、`rationale`。

**不是三支成片**，只是三張靜態板。但必須是真的渲染出來的畫面，不能只用文字描述。

```bash
cat > sample.json <<'J'
{"kicker":"02 近義介詞","title":"「對」有方向，|[[「跟」]]沒有","body":"同樣是介詞，「對」把動作射向一個對象。",
 "stat":"3.2","unit":"倍","stat_label":"「對」後接心理動詞的比例（示意）","nodes":["我","你"],"relation":"對",
 "caption":"「對」帶出的是動作的方向","breath":"差在方向"}
J
python scripts/style_apply.py chalkboard   --sample sample.json --out design-demos/A
python scripts/style_apply.py data-journal --sample sample.json --out design-demos/B
python scripts/style_apply.py my-new.json  --sample sample.json --out design-demos/C   # 邏輯③自訂的新風格卡
for x in A B C; do npx playwright screenshot --viewport-size=1920,1080 --wait-for-timeout=2000 \
  file://$PWD/design-demos/$x/board.html design-demos/$x.png; done
```
（標題用 `|` 手動分行、`[[ ]]` 標螢光筆。）

## 三套邏輯（三張各用一套，互不參考）

三張只換設計，內容相同（同一段旁白、同一批素材），才能橫向比較。**三張的版面骨架必須不同**（構圖、主角位置、資訊排列至少一項結構性不同），只換配色會被一眼看穿是換皮。

### 邏輯 ① 秒數輪盤（打破安全偏好）
執行 `date +%S`，`秒數 % 11` 對照 `style-library.md` 的輪盤表抽一張內建風格卡。抽到 `avoid_for` 列有這個科目的，重抽一次，並在說明裡寫為什麼。

### 邏輯 ② 標杆遷移
挑一個和這個主題最相關、做得最好的真實作品當標杆，拆解它的配色、字型、版面、招牌元素，再套到使用者的內容上。動手前先 WebSearch 確認這個作品存在、長什麼樣子。拆解結果直接寫成一張新風格卡（複製最接近的內建卡改，見 `style-system.md` §3），或選一張內建卡再用 `--set` 調參。常用標杆：
- 數學、證明：3Blue1Brown（深底、Manim、顏色即變數）
- 科普、抽象概念：Kurzgesagt、TED-Ed
- 時事、媒體素養：Vox、The Pudding（資料敘事）
- 中小學課程：均一教育平台、PaGamO 的教學動畫

### 邏輯 ③ 最佳設計師
想一想：**如果預算沒有上限，最適合為「這群學生、這個概念」做這支動畫的工作室或設計師是誰？**（例：原研哉、Pentagram、Studio Ghibli 的背景美術、Christoph Niemann、Sagmeister）用他的設計思維從頭設計，而不是模仿他的作品外觀。產出是一張**新的風格卡**（7 層參數都要填，色彩用三步推導），這也是風格庫長大的方式：使用者喜歡就把它存進 `assets/styles/`。

## 形式推導五問（每張方向板動手前先答）

風格是從內容長出來的，不是先選風格再塞內容。五問答完再定色彩和字型：

1. **教學角色**：這一幕在教學上是引起動機、建立概念、舉例、練習，還是統整？
2. **觀看距離**：教室投影（最後一排約 10 公尺）、平板（50 公分）、手機（30 公分）？距離決定字級和資訊密度。
3. **情緒溫度**：好奇、莊重、輕鬆、懷舊、緊張？決定配色和節奏。
4. **容量估算**：這一幕要放幾個概念、幾行字？先在紙上畫 3 張縮圖，確認塞得下。
5. **視覺母題**：這個內容特有、別的主題不會有的視覺元素是什麼？（講光合作用→葉綠體的綠與光線；講介詞→箭頭與方向；講孔子學琴→琴弦）母題是「設計從內容長出來」的最小證據。

每張方向板附一句「形式來自內容的哪裡」。寫不出來，就表示還在套模板，回去重答第 5 問。

## 執行方式

- **能開 subagent 的環境**（Claude Code）：同時開三個 subagent，每個只拿同一份 spec（主題、觀眾、腳本那一幕的旁白、素材路徑、尺寸 1920×1080、可讀性底線）＋各自的邏輯。spec 要寫具體（≥300 字），寫太薄三張都會跑偏。
- **不能開 subagent 的環境**：依序做三張。每張開始前只讀 spec，不參考前一張，用不同的錨點（輪盤號／標杆名／設計師名）避免三張長得一樣。仍然要做三張；真的吃緊才降級為「1 張主版＋2 張只換配色字型的變體」，並告訴使用者。
- 三張要**拉開溫度**（安靜／中性／大膽各一），版面骨架也要不同（風格卡的 `board` 欄：split／center／editorial／stage）。
- 三張都要過**可讀性底線**（`style-system.md` §6）：`style_apply.py` 列出的對比度警告要處理。

## 展示後停下

三張一起給使用者看，每張標明：用了哪套邏輯、具體是哪個風格／標杆／設計師、一句為什麼。**然後結束這一輪，等使用者選。**不要自己選了就繼續做。

使用者可以：選一張、混搭（「A 的配色＋C 的版面」）、微調、全部重來。

## direction-approved.md（選定後立刻寫）

```markdown
# 方向確認

- 日期：2026-10-07
- 展示版本：
  - A 輪盤 #2 chalkboard — design-demos/A.png
  - B 標杆 The Pudding → data-journal — design-demos/B.png
  - C 設計師 原研哉 → 新風格卡 kenya-white.json — design-demos/C.png
- 使用者原話：「B 的版面，但顏色用 A 的。」
- 定案：B 版面＋A 色票；hero element：一條會變形的資料線
- 套用指令：`python scripts/style_apply.py data-journal --colors-from chalkboard --out style/`
```

之後每一幕都只用 `style/` 裡的 tokens（`style-system.md` §2.3），並把風格 id 寫進 `storyboard.json` 的 `style`、方向板寫進 `direction`。
