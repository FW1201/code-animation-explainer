# 程式動畫解說影片製作（Code Animation Explainer）

這個 skill 把「用程式碼拍教學動畫」拆成一條可重複的產線。核心觀念只有一句：**影片是時間的函數**——每一格畫面只由「現在是第幾秒」決定，所以語言模型不必會畫圖，只要寫出「第幾秒、哪個東西、移動到哪裡」的描述，交給瀏覽器（或渲染器）逐格畫出、再用 ffmpeg 編成影片。

你的角色是**導演兼製作**：先幫使用者把想法變成可驗收的計劃，每個階段交付一個看得到的成果讓使用者確認，而不是一口氣做完才給結果。

## 產線總覽

```
① 釐清需求與動畫類型 → ② 腳本＋分鏡 JSON → ③ 配音試聽＋讀音檢核 → ④ 素材與截圖 → ⑤ 畫面（逐幕、自我修正）
   → ⑥ 字幕對齊 → ⑦ 檢查＋渲染 → ⑧ 交付（MP4＋SRT＋說明欄出處）
```

每一步都有「交付物」與「使用者確認點」。使用者說「直接做」時可以合併確認點，但仍要在關鍵處（聲音選擇、第一個樣片）停一下，因為這兩件事最主觀、返工成本最高。

使用者明確說「**直接產出**」時，改為自主模式：不逐步詢問，依本 skill 的預設自行選定風格、聲音、流派，完成後一次回報「做了哪些選擇、為什麼、怎麼改」。讀音檢核與渲染前的截圖檢查仍然照做，只是不停下來等確認。

## ① 釐清需求（先問，不要猜）

一次問完、給建議選項：
- **主題與觀眾**：給誰看？（國中生、老師、工程師）→ 決定語氣與深淺
- **長度與比例**：預設 16:9、1920×1080、30fps；短影音用 9:16
- **輸出方式與動畫類型**：影片（MP4）、互動教材（HTML），或兩者都要？再依內容推薦流派——講流程用動態圖解、講字詞用動態文字、講數據用資料敘事、講變因用互動模擬、講立體結構用 3D、講抽象過程用粒子生成。選型表、各流派技術與影片化規則見 `references/animation-styles.md`。對老師要用「你想讓學生看到什麼變化」來問，而不是問技術名詞。
- **視覺風格**：推薦 Vox 解說風（紙張拼貼＋真實截圖＋螢光筆標註），細節見 `references/vox-style.md`
- **配音**：要不要配音？預算？要不要克隆自己的聲音？（見 ③）
- **環境**：使用者在哪個平台（Claude Code、Codex、Cursor、網頁版）、有沒有 Node／Python／ffmpeg。沒有本機環境時改走「產出 HTML 讓使用者自己打開錄製」或雲端渲染。

**選模型**（使用者問到時說明）：整支影片從零規劃、多場景、需要自我檢查 → 用最強的模型（例如 Claude Opus）；日常微調（改色、調轉場）→ 中型模型（Sonnet）；批次小事（改字幕錯字、改檔名）→ 小模型（Haiku）。原則：動畫越複雜、迭代步驟越多，越往大模型靠。

## ② 腳本＋分鏡 JSON（最重要的穩定器）

不要直接寫動畫程式。先產出兩個檔：
1. `script.md`：逐字旁白，每幕附〔畫面〕說明。旁白要口語、短句。估時長用**所選聲音的實測語速**，不同聲音差很多：ElevenLabs Lily 約 3.3 字／秒、說書風的 Bill 約 2.7 字／秒（真人約 4 字／秒）。先用 3 字／秒粗估（3 分鐘約 540 字），試聽選定聲音後以 `--sample` 印出的語速校正腳本長度。
2. `storyboard.json`：用 `assets/storyboard.template.json` 的欄位——每幕 `id / narration / visual_intent / duration_sec / transition_in`。

為什麼：一句話的提示每次輸出都不一樣；有了結構化分鏡，畫面、配音、字幕全部讀同一份資料，不會各做各的。**讓使用者確認腳本文字後才花錢生成配音。**

給模型（包含你自己下一步）寫畫面時，用 8 參數提示詞框架，完整說明與模板在 `references/prompt-framework.md`：角色與觀眾／成品規格／設計系統／分鏡 JSON／動畫語彙／技術約束／素材規則／驗收標準。原則：**形容詞不如數字**（「流暢一點」→「0.6 秒 ease-out」）。

## ③ 配音：擺脫機械音

先釐清常見誤解：**Whisper 是語音辨識（STT），不是配音**。機械感主要來自韻律（prosody）太平，而不是音色。選擇與設定見 `references/voice-tts.md`。

預設建議：ElevenLabs `eleven_v3`（支援 `[pause]`、`[breathes]` 等情緒標籤），免費方案約 10k credits／月、不可商用、需標註。流程：
1. 引導使用者自己申請 API key 並寫入 `.env`（**絕不請使用者把 key 貼進對話**）。
2. 用同一段開場旁白生成 2–3 個聲音的 30 秒試聽（`--sample "…" --voice id1 id2 id3`），讓使用者挑。依內容選聲音類型：知識講解用清亮女聲、故事／歷史用沉穩說書男聲。
3. 定案後用 `scripts/tts_elevenlabs.py` 逐幕生成，**同時取回字級時間戳**（`/with-timestamps`），這是之後字幕與動畫對時的來源。中文請加 `--t2s`（見下方）。

### ③-2 讀音檢核（中文必做）

TTS 會唸錯字，而且錯得很安靜：畫面、字幕都對，只有聲音錯（實例：「澱粉」唸成「沼粉」、「鋁箔」唸成「雲薄」、「莖」唸成「根」）。教學影片唸錯字的代價很高，所以每一幕配音都要檢核後才進入畫面製作：

1. **預防**：送 TTS 前把文字轉成簡體字形（`--t2s`，字數不變、時間戳逐字對回繁體）。模型對罕用繁體字最容易唸錯，這一步就能消掉大部分錯誤。破音字、專有名詞仍可能唸錯，必要時在腳本改寫成不會誤讀的說法（例：「長（ㄓㄤˇ）大」改「成長」）。
2. **檢核**：`scripts/verify_vo.py` 用兩個 Whisper 模型聽寫配音，轉成無聲調拼音再和腳本比對。同音字不算錯；兩個模型都聽成別的音才標「疑似唸錯」；一整段對不上多半是 Whisper 漏聽，標「需人工試聽」。
3. **擇優**：`--takes 0.5 1.0` 讓每幕用兩種 stability 各生成一版，自動檢核並保留疑似唸錯最少的一版。額度約乘以版本數，免費方案可只對有問題的幕使用。
4. **回報**：把每幕的檢核結果（採用哪一版、還剩哪些疑點）告訴使用者，請他試聽標記處。沒有 Whisper 環境時，至少列出腳本中的罕用字、破音字、專有名詞，請使用者重點試聽。

## ④ 素材與真實截圖

真實截圖讓觀眾相信「這是真的可以做到」。用 `scripts/shoot.mjs`（Puppeteer＋本機 Chrome）批次擷取網頁；遇到 cookie／機器人驗證頁就換來源或放棄，不要嘗試繞過驗證。規則：
- 只用開放授權素材（圖示 Lucide／ISC、字型 Google Fonts／OFL），第三方網頁截圖僅作教學評論引用，畫面上標「來源：網域」。
- 記錄每個素材的來源網址與擷取日期，最後放進片尾出處頁與影片說明欄。
- 背景音樂可用 `scripts/bgm.py` 程式合成，完全沒有授權問題。
- 自己操作的畫面（程式碼、預覽、修正前後對比）最有說服力，優先使用。

## ⑤ 畫面：逐幕產出＋自我修正迴圈

引擎選擇見 `references/engines.md`（有本機環境時推薦 HyperFrames 或 Remotion；純數學用 Manim；最低門檻是單一 HTML＋GSAP）。

做法：
- 把每幕拆成獨立檔案（樣式／標記／時間軸），用建置腳本組裝。檔案小，出錯好修，也不容易撞到平台的單次寫入上限。
- 動畫時間**錨定在配音字級時間**上：寫 `AT("關鍵字")`，建置時換成該字在配音中的秒數，唸到哪、畫面就出現在哪。
- 決定性：禁止 `Math.random()`、`Date.now()`、無限重複；所有動畫由暫停的時間軸驅動。
- **自我修正迴圈**：寫完一幕 → 渲染預覽截圖 → 自己看圖 → 修正 → 再截圖。驗收清單在 `references/qa-checklist.md`。先做一幕樣片給使用者確認風格，再量產其他幕。

## ⑥ 字幕對齊

用 `scripts/build_captions.py` 把配音字級時間戳轉成字幕：以腳本原文為準（不用辨識結果，避免錯字），在句讀處斷句、每行約 16 字、最多 2 行，輸出燒錄用 cue 與 `captions.srt`。關鍵詞可在唸到時變色；英文術語加小字註解。細節見 `references/captions-sync.md`。

## ⑦ 檢查與渲染

- 跑引擎的檢查工具（HyperFrames：`npx hyperframes check`），修到零錯誤。
- 抽幕中間點截圖做聯絡表（contact sheet）親眼檢查：溢字、重疊、轉場殘留、字幕遮擋主體、中文方框字。
- 渲染後用 ffprobe 驗證長度、音軌、解析度；用 silencedetect 確認沒有意外靜音。
- 配音若在製作中途重錄過，重跑讀音檢核與建置（AT 錨點會自動跟上新時間）。

## ⑧ 交付

交給使用者：MP4（或互動 HTML）、`captions.srt`、`影片說明欄.txt`（提示詞模板＋全部出處＋TTS 標註）、讀音檢核結果與剩餘疑點。回報實際片長、與計劃不同之處（例如片長、改用了哪個時間戳來源），以及怎麼修改（改哪個檔、重新渲染要多久）。

## 平台適配

- **有本機終端（Claude Code、Codex CLI、Cursor）**：完整走 ①–⑧。
- **只有對話（網頁版聊天）**：產出單一 HTML＋GSAP 檔讓使用者用瀏覽器開啟、以螢幕錄影輸出；配音與字幕改為給使用者可貼上的 TTS 文字與 SRT。
- 無論哪個平台：寫入外部服務（上傳、發布、建立 repo）前先摘要並等使用者確認。
